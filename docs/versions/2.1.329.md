# Claude Code v2.1.329 更新日志

> 🗓 2026-11-19 发布 · 📋 130 条更新（🚀 7 · 🔧 11 · 🔄 21 · 🐛 91）

**✨ 本版亮点**

- 🐛 **关键修复**：修复 `~/.claude.json` 因网络停滞或文件锁被重置为默认配置的问题
- 🐛 **关键修复**：修复 macOS 下 Keychain 无法写入导致反复登出，现仅过期会话受影响
- 🔧 **改进**：优化长会话及 Code Mode 大量工具调用后的内存占用，防止内存失控
- 🚀 **新功能**：`/tasks` 新增显示本会话定时任务、`/loop` 唤醒与对话分支
- 🐛 **关键修复**：修复 `/code-review <pr 编号>` 可能误审当前分支而非目标 PR 的问题

**📋 更新明细**（共 130 条，按类别归组）

**🚀 新功能**（7 条）

- 新增信任对话框警告，指明文件夹的 hooks 声明位置
- 新增会话内警告：在 Claude Desktop 及其他非交互式宿主中，受管设置里的 hooks 加载失败时会提示
- 将本会话的定时任务、`/loop` 唤醒、目标及当前对话的分支加入 `/tasks`；x 会在询问后停止其中一项
- 在 `/mcp` 的服务器页面新增“Server message”行，显示拒绝连接的远程 HTTP MCP 服务器的 JSON-RPC 错误消息
- 在 `/status` 新增“Marketplace auto-update”行，列出不会自动更新的受管 marketplace 及原因
- 新增在启用 OpenTelemetry 事件和指标的同时开启 Code Mode 的支持；代码的每次工具调用都会发送事件；tracing 仍会将其关闭
- [VSCode] 在你拒绝信任提示后，于消息框上方新增一行，提供 Review trust 可重新调出提示，无需重载窗口

**🔧 改进**（11 条）

- 改进了带有托管设置的计算机上旧会话的自动清理
- 改进了 `/tui` 及其他原地重启方式，会短暂等待登录刷新，从而降低被登出的概率
- 改进了编辑大量文件的长会话，以及在 macOS 和 Linux 上包含大量大型 MCP 工具结果的长 Claude Desktop 会话的内存占用
- Windows：改进了 Claude Code 的搜索程序启动缓慢的 PC 上的启动速度和首次搜索速度
- 改进了 auto mode 在关闭遥测、通过网关访问 Anthropic API 或使用 Microsoft Foundry 时，对 Claude 问题给出「yes」等简短回复的处理
- 改进了长对话轮之后、以及 `--resume` 或 `--continue` 包含截图或大型工具结果的会话之后，空闲的 Claude Desktop 和 SDK 会话的内存占用
- 改进了开启 Remote Control 的 Claude Desktop Code 会话在回答后可更快接收下一条消息
- 改进了云会话，会重试启动时下载失败的插件
- 改进了 Code Mode：脚本进行数千次工具调用后终端冻结时间大幅缩短
- 改进了 Code Mode：启动 subagent 后，Claude 现在会获得与 Code Mode 之外相同的等待指引
- 更新了 macOS 上的 computer use 安全规则，部分操作将被拒绝，部分应用的访问权限有所收紧

**🔄 变更**（21 条）

- 变更了已保存的定时任务：在新的登录会话中，早期版本保存的大部分任务需要重新排期，但对自身会话执行 `--resume` 仍会运行它们
- 变更了 `/code-review` 在大多数模型上不指定目标时，改为将整个分支与默认分支对比审查，并修复了其在多提交分支上丢失 diff 的问题
- 变更了 auto mode，减少 `git status` 的执行频率，使大仓库中多数请求等待时间更短；丢弃更改的 git 命令可能会被暂缓，直至工作区检查完成
- 变更了 `/code-review <pr number> --fix` 及传入 pull request URL 的 `/code-review`，当 `gh pr diff` 被拒绝或失败时会直接停止而不进行审查
- 变更了「Exit and stop tasks」行为，现在会结束本会话的定时任务，使其在恢复会话后不再运行，除非在 Claude 正在回复时退出
- 变更了部分队友面板改用 /bin/sh 启动，因此可能不会读取 shell 启动文件
- 更改了 macOS 上的 computer use：应用启动超过 30 秒仍未完成时将放弃等待
- Gateway：将 `access_control.allow_cidrs` 为空时的启动警告改为每次启动都显示的提示，并以文本日志框出：切勿将 gateway 暴露到公共互联网
- Self-hosted runner：更改了第二个主机的同名 owner/name 克隆的存放位置，改放在基础文件夹下的 `_repos/clones/<host>/`；已有克隆不会被移动
- Self-hosted runner：地址路径中含异常字符的仓库改为在新文件夹中重新克隆；引用旧文件夹的规则和卷命名将不再生效，旧克隆保留原地
- Self-hosted runner：更改了 `--repository-folder`，在 `--capacity 1` 时可接受基础文件夹中的大多数文件夹（容量大于 1 时，其中存在文件夹会阻止启动）；其他仓库的会话若与之重叠将被拒绝
- 更改了 Code Mode：出错的 PreToolUse hook 不再拒绝脚本的工具调用，与 Code Mode 之外的行为保持一致；如必须拒绝，请在命令、HTTP 或 MCP 工具 hook 上设置 `"onFailure": "block"`
- 更改了 Code Mode：拒绝脚本读取超过 256 MiB 的行范围（此前可能消耗数 GB 内存），并修复了超长行读取超时的问题
- 更改了 Code Mode：在关闭遥测、非必要流量或 feature flags 时也能启动；管理员可通过 managed settings 保持其关闭
- 更改了 Code Mode：允许运行自行声明 `log`、`preview` 或 `sleep` 的脚本（此前会被拒绝）
- 更改了 macOS 登录续期方式：使用 `Claude Code-write-check` 项测试 Keychain
- 更改了 `/tasks` 头部和底部的后台计数：合并为一个数字，涵盖 shell、monitor、MCP 调用、agent、workflow 和定时任务
- 更改了 Stop 和 SubagentStop hook：在 `background_tasks` 中将 Monitor 的脚本列为 `monitor` 而非 `shell`
- 移除了 2.1.326 中针对 `max_tokens` 错误所指示上限的自动重试；若 gateway 后的模型输出 token 上限较低，请将 `CLAUDE_CODE_MAX_OUTPUT_TOKENS` 设为该上限
- [VSCode] 更改了 Down 键行为：在权限提示的最后一项处停止，不再循环回到 Yes
- [VSCode] 更改了命令输出显示方式：将隐藏字符及纯颜色以外的控制序列显示为符号，因此波斯语、高棉语、老挝语、僧伽罗语和马拉雅拉姆语文本可能出现显示破损或顺序错乱
