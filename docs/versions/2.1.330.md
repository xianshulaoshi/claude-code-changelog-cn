# Claude Code v2.1.330 更新日志

> 🗓 2026-11-20 发布 · 📋 142 条更新（🚀 16 · 🔧 14 · 🔄 14 · 🐛 98）

**✨ 本版亮点**

- 🚀 **新功能**：支持登录 Anthropic 企业管理控制台中的组织，自动应用组织设置与云网关
- 🚀 **新功能**：新增内置图表工具 easel，可按需绘制图表，可在 /config 中关闭
- 🚀 **新功能**：VS Code 新增 /fork 命令，可在最后一条回复后分叉对话
- 🐛 **关键修复**：修复压缩超长对话后 Claude Code 卡死数分钟，以及 WebFetch 长时间冻结会话的问题
- 🐛 **关键修复**：修复多个 Claude Code 进程同时保存时用户设置丢失的问题

**📋 更新明细**（共 142 条，按类别归组）

**🚀 新功能**（16 条）

- 新增登录到 Anthropic Enterprise Admin Console 管理的组织：执行 `claude auth login` 后，Claude Code 会应用该组织的设置，并使用其云提供商或网关
- 新增内置 mod easel：可按需绘制图表，也会在 MCP 指标结果下生成图表；适用于 Pro、Max 以及（可用的）Team 和 Enterprise 计划，支持 macOS 和 Linux；可在 `/config` 中关闭自动图表
- 新增 `CLAUDE_CODE_FULL_SIGN_IN_LINK=1`，用于打印完整的登录链接，适用于短链接报错或脚本需要从中读取值的情况
- Self-hosted runner：新增 `--start-dir` / `SELF_HOSTED_RUNNER_START_DIR`，让 Claude 从仓库的某个文件夹开始工作，同时设置和 hooks 的加载方式与不指定时一致
- 当插件市场因其仓库不属于当前会话的仓库而无法获取时，在云和 self-hosted runner 会话中新增提示
- Self-hosted runner：当 Anthropic 管理的 git 拒绝插件自带的仓库时新增提示，会指明插件名称及处理方式
- `claude plugin install --json` 结果新增 `commandPrinted`（插件的安装命令向 stderr 写入内容时为 true）和 `commandFailed`（命令出错退出、被终止或超时时为 true）
- Self-hosted runner 的 `/metrics` 新增 `claude_code_self_hosted_runner_order_to_registered_seconds`：在编排器启动的 runner 上，从工单下发到注册接受的秒数
- Self-hosted runner 的 `/metrics` 新增 `claude_code_self_hosted_runner_order_to_first_session_seconds`：在为会话启动的 runner 上，从工单下发到首个会话交接完成的秒数
- [VSCode] 新增 `/fork` 命令，可在最后一次回复后 fork 对话（anthropics/claude-code#69272）
- [VSCode] 新增 `/workflows` 命令，打开代理地图并显示运行中的 workflows
- [VSCode] 新增 `claudeCode.escapeStopsClaude` 设置；关闭后 Esc 不再停止 Claude（anthropics/claude-code#91536）
- [VSCode] 新增 `claudeCode.pinPrompt` 设置，可让输入的消息随页面滚动而非固定置顶
- [VSCode] 新增 `claudeCode.contextUsageThreshold` 设置，控制上下文指示器的显示时机（anthropics/claude-code#93036）
- [VSCode] 为 "Open in Side Bar" 命令新增 `prompt` 参数，方便快捷键和扩展使用
- [VSCode] 会话分组菜单新增上移和下移选项（anthropics/claude-code#98654）

- 改进 `/resume`：不再列出只打开过 `/model` 等界面后就离开的会话
- 改进 `/mcp` 和 `/plugin` 中的 Reconnect：服务器仍然失败或需要登录时，服务器页面保持打开并显示原因
- 改进 macOS 上 sandbox 拒绝列表过长时的错误提示：现在会指出过长的列表及缩短方法
- 改进全屏模式下的 `/plugin`：有错误的插件页面现在以这些错误开头
- 改进 Team 和 Enterprise 计划上 `/ultrareview` 的费用确认：当月度支出限额剩余额度低于一次审查的通常费用时会予以提示
- 改进 Amazon Bedrock 或 Google Cloud Agent Platform 上的自托管 runner 会话：因账户拒绝首选模型而使用其他默认模型启动时会明确说明
- Windows：改进会话文件夹位于 Claude Code 无法验证的驱动器时的错误提示：说明原因及重试是否有帮助
- 改进 Code Mode：现在会告知 Claude 如何查看图片和 PDF
- 改进 Code Mode：按 Esc 后，停止的命令下方现在显示 "Interrupted" 而非红色错误
- 改进了 Code Mode：subagent 脚本执行数千次工具调用后，终端卡顿时间大幅缩短

**🔄 变更**（14 条）

- 回退 2.1.329 中移除的 `max_tokens` 超出模型或网关限制时的自动重试
- 定期计划任务和 `/loop` 在会话保持运行的情况下，最长可持续运行 30 天（原为 7 天），并会在结束时告知；此版本之前创建的任务仍在 7 天时结束
- 更多针对根目录、home 目录、顶层目录或工作目录的 `rm` 命令改为需要批准；无人可应答时将直接拒绝执行
- `deniedMcpServers` 中的名称条目现在仅隐藏对应名称的 claude.ai connector，不再隐藏同一 URL 下的其他 connector；如需全部屏蔽，请拒绝其确切 URL
- 在某些环境下，`claude --teleport` 改为打印切换分支的 git 命令而非直接执行；使用 `-p` 时，在切换完成前将以退出码 1 退出
- 包含 "sonnet" 或 "haiku" 的未识别模型名称现在与其他未识别名称一样使用较短的系统提示词；设置 `CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0` 可让所有模型使用完整提示词
- Claude 运行的带有 `model` 设置的 skills（`context: fork` 类 skills 除外）不再影响 subagent、fork、压缩和 `/recap`，它们仍使用会话的模型
- subagent 的模型回退机制现在可以传递：未指定模型的 agent 及其随后启动的 fork 将运行在回退模型上，且它们启动的 agent 会沿用其 Bedrock 区域
- 自托管 runner：`spawn-runner` hooks 现可并行启动（此前需等前一个运行完），每个 orchestrator 默认上限为 `--hook-concurrency`（默认 4）；如你的 runner 无法并行运行，请将其设为 1
- 自托管 runner：Bash 命令在无需文件 diff 时会跳过它，因此转录中可能缺少 diff；在受管设置中将 `bashEditDiffEnabled` 设为 true 可获取每次 diff
- checkout hook 以状态码 108 退出时，自托管 runner 将立即停止该会话的启动，不再尝试其他 runner
- prompt hooks 的 `model` 字段现在支持模型别名，如 `haiku` 或 `sonnet`
- `/design-sync` 的参考 Storybook 回退构建现在仅使用项目内安装的 Storybook
- 在通过 Claude apps 网关登录的终端会话中，subagent 进度摘要改为基于简短笔记而非完整对话生成，token 消耗大幅降低
