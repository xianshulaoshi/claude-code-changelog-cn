# Claude Code v2.1.332 更新日志

> 🗓 2026-11-24 发布 · 📋 150 条更新（🚀 11 · 🔧 20 · 🔄 26 · 🐛 93）

**✨ 本版亮点**

- 🚀 **新功能**：支持加载来自 MCP 服务器的 skills（beta），在 `/` 菜单中以 `server:skill` 形式显示
- 🚀 **新功能**：新增 PreSkillShellCommand hook 事件，可在 skill 或命令加载时拒绝其内联 shell 命令
- 🐛 **关键修复**：修复多处卡死问题：hook 无限输出、通配符权限规则匹配长命令、MCP 服务器刷屏导致终端无响应等
- 🐛 **关键修复**：修复 `claude auth login` 在凭据无法保存时误报成功，现在会退出并提示排查方向
- 🔧 **改进**：显著改进长会话恢复和大工作区的内存占用与性能，降低 `claude -p` 和 SDK 会话启动内存

**📋 更新明细**（共 150 条，按类别归组）

**🚀 新功能**（11 条）

- 新增 MCP 服务器技能（beta）。它们在 `/` 菜单中显示为 `server:skill`；其他技能保持原名称不变
- 新增 `PreSkillShellCommand` 钩子事件，可在技能或命令加载时拒绝其内联 shell 命令；在 2.1.331 及更早版本中，命名该事件的设置文件会在启动时弹出对话框
- 为来自其他会话的被暂留消息的提示新增 "始终送达" 选项
- 当被标记消息使会话运行在其他模型上时，新增一行持续显示的页脚提示，直到你用 `/model` 选定模型
- 当启用响应日志记录时，新增 OpenTelemetry `assistant_response` 事件，用于 Claude 通过 SendUserMessage 或 Cowork 消息工具发送的文本
- 在 VS Code 和 Desktop 的 Code 标签页中新增警告，当会话的某部分无法保存时，会提示如何用 `/compact` 保存
- 在 VS Code 和 Desktop 的 Code 标签页中新增提示，当恢复的会话未加载早期消息时显示，与终端中的提示一致
- 将你的 Cyber Verification Program 访问层级显示在启动头部，当该层级适用于当前模型且你使用 claude.ai 账户登录时，显示在模型名称旁
- [VSCode] 新增：关闭建议 diff 而未应用编辑时在更多情况下显示通知，并停止对已答复 diff 的拆分副本显示 diff 通知
- [VSCode] 新增：在侧栏使用 `/rewind` 恢复对话导致自步进 `/loop` 停止时显示警告
- [VSCode] 新增：Manage plugins 列表中显示已安装的版本

**🔧 改进**（20 条）

- 改进了 Windows 上的 `claude plugin marketplace add`：当杀毒软件等其他程序短暂占用已下载文件时，会等待并重试
- Windows：改进了部分公司电脑上的稳定性，此前 Claude Code 可能在启动后不久无输出退出
- 改进了 computer use 设置：屏幕录制权限提示现在可以重启 Claude Code 并恢复会话
- 改进了 computer use：在 Claude 实际使用前占用更少上下文
- 改进了代理或网关截断或损坏压缩响应时的错误提示：回合现在以通俗文字结束，而非原始的 "ZlibError fetching" 文本
- 改进了 `/context`：全屏下输出更简短，在矮窗口中总量不易滚出屏幕，图例中的单位只命名一次
- 改进了 `/usage` 在有大量近期会话的机器上的峰值内存和速度
- 改进了 `/permissions`：拒绝会在下次启动时被跳过的规则（如未指定工具名的 `rm -rf`），并显示原因
- 改进了在 Code Mode 中恢复会话：现在会提前告知 Claude 其先前的脚本变量已丢失
- 改进了 Code Mode 中的 Claude：在丢弃 worktree 更改前先确认，发布前先读取 artifact 文件，并更新现有 artifact 而非重复创建
- 改进了 Code Mode 的工具搜索：在空间允许时完整显示较长的 MCP 工具描述，因为截断的描述可能导致错误调用
- Linux：改进了 Ctrl+V 提示，无法从剪贴板读取图片时会指明需安装的软件包（`wl-clipboard` 或 `xclip`）
- 改进了在有请求大小限制的代理或网关后恢复长对话的能力，此前每条消息和 `/compact` 都会报 413 错误
- 改进了 Windows 上拥有 6 个及以上 CPU 的机器中大型本地文件夹的 Glob 速度：文件夹并行遍历，达到时间上限时搜索会列出已找到的结果
- 改进了恢复长会话时的内存占用
- 改进了启动时 MCP 服务器列出大量工具情况下的内存占用
- 改进了 `claude -p` 和 SDK 托管会话在会话开始时的内存占用
- 更新了 macOS 上 computer use 的安全规则，部分操作会被拒绝，输入可能变慢
- [VSCode] 优化：打开 Claude 面板和长会话的耗时、长回复流式传输时的性能，以及超大工作区中读取诊断信息的速度
- [VSCode] 优化：在纯文本标签页中打开的命令和单行输出现在会自动换行

**🔄 变更**（26 条）

- 更改了 Bedrock Mantle、Agent Platform 和 Foundry 上迁移至 Sonnet 5 或 5.5 的终端和 VS Code 会话：未设置模式时将以 auto 模式启动；设置 `disableAutoMode` 为 `"disable"` 可停止此行为
- 更改了 Google Cloud Agent Platform 和 Microsoft Foundry 上的 `sonnet` 模型别名为 Sonnet 5.5，Foundry 的 `opus` 别名为 Opus 5.5；Amazon Bedrock 上的 `sonnet` 保持 Sonnet 4.5
- 更改了 Microsoft Foundry 上的默认模型为 Sonnet 5.5：请部署 `claude-sonnet-5-5`，或将 `ANTHROPIC_DEFAULT_SONNET_MODEL` 设置为已部署的模型
- 更改了 Google Cloud Agent Platform 上的 `sonnet` 和后台请求，改为读取 `VERTEX_REGION_CLAUDE_5_5_SONNET`；仅设置 `4_5` 变量时将使用 `CLOUD_ML_REGION` 或 `us-east5`
- 变更：`--model default` 和“Default”选项在所选模型不可用时自动切换到较旧的模型，而不是报错停止；在 auto 模式下仅切换到 auto 模式可接受的模型
- 变更：Microsoft Foundry 方面，Claude Sonnet 4、Opus 4 和 Opus 4.1 现被标记为已停用，降级会在这些模型之上停止，固定使用其中某个模型时会提示其已停用
- 变更：Claude 应用网关内置模型列表中，Sonnet 5.5 取代 Sonnet 4.5 成为第二个模型；在策略不允许使用 Opus 4.6 时，Claude Desktop 将默认启用它
- 变更：SDK 和 `claude -p` 的轮次中消息在无法获取功能开关时（如云端环境或关闭遥测），自 Opus 4.8 起计为用户消息；转发文本会标记 `isSynthetic: true`
- 变更：`computer-use` 在启用计算机使用的 Mac 上成为保留技能名，同名的自定义技能或命令将停止加载，启动时会有提示要求重命名
- 变更：桌面 Code 标签页会话的 OpenTelemetry 默认 `service.name` 改为 `claude-code-desktop`；请更新以 `claude-code` 为键的过滤器，或设置 `OTEL_SERVICE_NAME` 以保留旧名称
- 变更：OpenTelemetry `tool_input` 仅显示通过 SendUserMessage 或 Cowork 消息工具发送文本的长度，除非开启响应日志（`OTEL_LOG_ASSISTANT_RESPONSES=1`）
- 自托管 runner：变更：`CLAUDE_CODE_OAUTH_TOKEN` 前缀现在可以以 `oat02-` 或 `oat01-` 结尾。请更新匹配 `oat01-` 的代理规则和日志脱敏规则，并遮蔽整个值
- 变更：`claude self-hosted-runner setup` 在 macOS 和 Linux 上无参数运行时，会在 Claude 启动前于终端中询问环境密钥，并在粘贴时隐藏输入
- 变更：Claude Desktop 的 Code 标签页在 Anthropic API 上会忽略自有设置中不以 `claude` 开头的默认、侧请求、别名和子代理模型 ID（网关地址旁的设置除外）
- 变更：Claude Desktop 的 Code 标签页在 Anthropic API 上会忽略自有设置中低于 200K 的 `CLAUDE_CODE_AUTO_COMPACT_WINDOW`（网关地址旁的设置除外）；请改用 `/autocompact`
- 变更：桌面应用 Code 标签页和 VS Code 中的计划模式，当无 auto 模式安全检查可判定某命令时，对于 Manual 或 Accept edits 下输入的计划改为请求批准而非直接拒绝
- 变更：PgUp 和 Home 键在破坏性问题（如从代理视图执行 `/clear`）中移至“No”选项
- 变更：终端中的 `/feedback` 草稿默认打开在“Not now”选项上，其上方有单独的行可分别选择仅发送报告或连同对话记录一起发送
- 变更：点击式语音听写现在可在 60 秒无新词或 10 分钟后才关闭麦克风（此前为 15 秒和 2 分钟），之后文本保持未发送状态，下次点击可继续追加
- 变更：点击式语音听写在发送提示词时停止；在编辑提示词、面板遮挡、连接丢失或检测到其他录音程序时停止并说明原因
- 变更：`/schedule`、权限提示和 `/loop` 的云端提议改用“cloud scheduled task”表述，替代“routine”或“cloud schedule”；`/routines` 仍然可用
- 变更：从 Claude 移动应用或 claude.ai 切换模型时，若新模型未保存努力级别，将沿用上一个模型的设置
- 变更：mod 的 `PromptHint` 钩子收到的 `hint`，在全屏页脚右侧有标签时不再包含所选文本的提示
- 变更：`awsCredentialExport` 现在在 10 分钟后超时，而不是无限等待
- [VSCode] 变更：语音听写现在在 60 秒无识别语音或 10 分钟后自动停止（此前为 15 秒和 2 分钟），麦克风可保持更长时间的开启
- [VSCode] 变更：麦克风停止发送音频或面板持续隐藏时，语音听写会停止并说明原因
