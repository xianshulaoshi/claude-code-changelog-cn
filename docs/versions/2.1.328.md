# Claude Code v2.1.328 更新日志

> 🗓 2026-11-18 发布 · 📋 144 条更新（🚀 14 · 🔧 19 · 🔄 20 · 🐛 91）

**✨ 本版亮点**

- 🚀 **新功能**：Claude Opus 4.6 和 Sonnet 4.6 在 Bedrock、Agent Platform、Foundry 等平台新增 auto 模式
- 🔧 **改进**：大幅改进 Code Mode：脚本提速、实时显示命令输出、编辑失败时告知最接近匹配位置
- 🐛 **关键修复**：修复 zsh 中 Bash 命令在以 = 开头的词处报错停止的问题
- 🐛 **关键修复**：修复自动压缩沿用旧系统提示词而非像 /compact 那样重建的问题
- 🔧 **改进**：加快大尺寸会话恢复速度，降低多图片会话与长会话的内存占用

**📋 更新明细**（共 144 条，按类别归组）

**🚀 新功能**（14 条）

- 为 Amazon Bedrock、Google Cloud 的 Agent Platform、Microsoft Foundry 和 Claude apps gateway 上的 Claude Opus 4.6 与 Sonnet 4.6 新增 auto 模式；未设置权限模式的交互式会话将默认以该模式启动
- 为 `mcp_tool` hooks 新增 `"onFailure": "block"`，与命令和 HTTP hooks 一致：hook 调用失败时将阻止该操作
- 新增警告：当某个跳过权限提示的会话发出的消息可能被云端会话挂起并丢弃时进行提示
- 在 `/status` 和 `claude doctor` 中新增提示：当 OpenTelemetry exporter 未配置 endpoint 时，其数据很可能会丢失
- 新增 `CLAUDE_CODE_DISABLE_DEFERRED_TOOL_RESUME`，允许宿主环境阻止 `claude -p --resume` 和 `--continue` 运行被 hook 延迟的工具调用
- 新增支持：嵌入 Claude Code 的应用可启用策略插件的 `allowManagedModsOnly` 选项；管理员的托管设置仍优先
- 当策略的 `maxEffortLevel` 不是有效的 effort 级别时，Claude apps gateway 在启动时新增相应警告
- Self-hosted runner：新增 `--repository-folder`，用于在 `--capacity 1` 时为仓库指定会话使用的文件夹名称，替代其在基础文件夹下的路径（该路径不能是符号链接）
- Self-hosted runner：当宿主 settings.json 设置了会话会忽略的默认权限模式时，启动时新增警告
- Self-hosted runner：为 `claude self-hosted-runner orchestrator` 新增 `--hook-label`，可将选定的会话标签传递给 `spawn-runner` hook
- Self-hosted runner：为 `claude --environment` 新增 `--metadata key=value`，用于为会话添加标签以供 `spawn-runner` hook 使用
- Self-hosted runner：在 orchestrator 的 `/metrics` 中新增 `claude_code_self_hosted_orchestrator_session_queue_wait_by_reason_seconds`，可区分重新打开的会话与新会话的等待时间
- Self-hosted runner：新增 orchestrator 指标 `claude_code_self_hosted_orchestrator_sessions_given_up_total`，按原因统计 Anthropic 放弃为会话启动 runner 的次数
- [VSCode] 新增当来自其他会话的消息被暂存时的通知，并附上可允许其通过的设置文件链接

**🔧 改进**（19 条）

- 改进 `claude -p` 和 SDK 会话，使其在后台拉取拥有独立 git 仓库的托管设置（managed-settings）插件，供后续会话使用
- 改进 `claude -p`、SDK 和 Claude Desktop 会话中来自 git marketplace 的托管设置插件在全新机器上的加载速度；短时运行可能会晚最多 30 秒退出
- 缩短恢复大型会话所需的时间
- 降低恢复包含大量图片的会话时的内存占用
- 降低长时间运行缓慢命令或工具的 SDK 和桌面会话的内存占用并缩短响应时间
- 改进 Code Mode 在 auto 和 bypass-permissions 模式下的速度，移除了大多数脚本后的 0.75 秒暂停
- 改进带有 MCP 服务器的新 Code Mode 会话的提示缓存（prompt caching），并且 Claude 现在会被告知某个服务器仍在连接中以及服务器列表何时变化
- 通过更短的工具描述改进 Code Mode 的 token 使用
- 改进 Code Mode：脚本运行时现在会显示其正在执行的命令及输出
- 改进 Code Mode 的编辑操作：无实际更改的编辑不再中止脚本，并且 Claude 会被告知失败的编辑在何处匹配或最接近的位置
- 改进 Code Mode：Claude 现在会被告知脚本失败时哪些工具调用仍在运行
- 改进 Claude 在 Code Mode 的 auto 和 bypass 模式下启动开发服务器的方式：Claude 会被要求将其作为后台任务运行，并显示在 `/tasks` 中
- Windows：改进 Code Mode，告知 Claude 脚本的 shell 命令运行在 Git Bash 中，且 PowerShell 的别名会优先于同名函数执行
- 改进同时启动多个进程内 teammate 的体验：出现 "Lock file is already being held" 失败的情况大幅减少
- 改进 computer use 审批对话框：现在会显示每个应用的访问权限级别和更直白的警告
- 改进跨会话消息传递：当云端会话或另一台计算机未列出时，Claude 现在会说明 Remote Control 已关闭
- 改进 `claude -p` 的文本输出：当来自其他会话的消息被暂存或丢弃时，会在 stderr 上说明情况及如何允许其通过
- 改进 Claude 对“谁能打开其发布的 artifact”的回答：Claude 现在会被要求重新检查 artifact，而不是重复上次发布时的答案
- 改进恢复的 self-hosted runner 会话：Claude 现在会检查其之前的工作是否仍在，并说明缺失的内容

**🔄 变更**（20 条）

- 变更第三方提供商上 Opus 4.6 和 Sonnet 4.6 的计划模式（plan mode）和 Bash 提示，改为使用并提供 auto 模式，与较新模型保持一致；`disableAutoMode` 可同时关闭两者
- 变更 Code Mode：不再对脚本输出运行 UserPromptSubmit hooks（包括托管 hooks）；如需对输出进行脱敏，请使用带 `updatedToolOutput` 的 PostToolUse hook
- 变更大多数模型上的 `/code-review`，仅报告 bug 和 CLAUDE.md 违规；如需复用、简化和效率方面的清理，请运行 `/simplify`
- 变更 `/code-review`：在大多数模型上会将每个发现标记为 Important、Pre-existing 或 Nit，并在每条总结末尾给出建议的修复方式；通过审查的列表现在显示为 "Code review found no issues."
- 变更 `deniedMcpServers` 中形如 `claude.ai <name>` 的条目，使其在云端和 self-hosted runner 会话中同样适用于该连接器
- 变更托管的 `PostToolUse` hooks：不再对运行前即被拒绝的调用触发——不再产生日志条目、重写、拦截或停止；`PostToolBatch` 会接收大多数此类事件，但不标记为被拒绝
- 变更 `/bug` 在发送前询问 Yes 或 No，避免连续按 Enter 误发报告或打开 GitHub
- 变更 `claude -p`、Agent SDK、桌面版和 VS Code 中的 subagents：在设置 `CLAUDE_CODE_FORK_SUBAGENT=0` 时默认等待其自身的 subagents
- 变更设置 `CLAUDE_CODE_FORK_SUBAGENT=0` 时的 `claude -p`：后台 subagent 及其等待的对象共用一个 10 分钟等待额度；更长的链路请调高 `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS`
- 变更被 PermissionRequest hook 重写为沙箱排除命令的 shell 命令，使其在沙箱外运行
- 变更 Claude in Chrome 欢迎界面和 `/chrome` 的说明：Claude Code 会在 Claude 对网站执行操作前进行询问，除非你的权限模式或 `/permissions` 中的规则已给出答复
- 变更第三方提供商上或关闭了遥测/功能开关的 Claude Desktop 和 Agent SDK 会话：在存在未回答的问题时关闭会话会结束当前轮次，而不是在没有答案的情况下继续
- 变更粘贴文本会被标记为粘贴内容告知 Claude（在第三方提供商上或关闭遥测/功能开关时同样生效）
- 变更终端会话中 subagent 进度摘要的生成方式：在 Anthropic API 上改由默认的小型快速模型根据简短笔记撰写（遥测关闭时同样生效），token 消耗大幅降低
- 变更无法启动沙箱时的报告方式（除非设置了 `sandbox.failIfUnavailable`）：下一条沙箱化的 Bash 命令会被拒绝，并说明本会话中沙箱已关闭
- 变更 `/list-agents` 仅向你本人显示列表；Claude 会在需要时自行列出会话
- Self-hosted runner：变更内置 `gh api` 在设置按名称守护 Claude 的 GitHub 工具时默认关闭；`--use-anthropic-gh true` 可开启
- Self-hosted runner：变更包装脚本在会话自身的 `claude` 启动前或结束后运行的 `claude`，使其不使用 Anthropic 管理的 git
- Self-hosted runner：变更 `CLAUDE_RUNNER_SESSION_UUID` 和 `CLAUDE_CODE_REMOTE_SESSION_UUID`，两者现在都会为会话及其 `checkout`、`post-session` 和 `spawn-runner` hooks 设置
- 变更 `--capacity 1` 的 self-hosted runner：当其推送的仓库路径为符号链接时，会更早拒绝会话
