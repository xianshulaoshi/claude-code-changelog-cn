# Claude Code v2.1.328 更新日志

> 📋 144 条更新（🚀 14 · 🔧 19 · 🔄 20 · 🐛 91）

**✨ 本版亮点**

- 🚀 **新功能**：Opus 4.6 与 Sonnet 4.6 在 Bedrock、Agent Platform、Foundry 等第三方平台支持 auto mode，交互会话默认启用
- 🔧 **改进**：Code Mode 提速并实时显示脚本运行中的命令与输出，编辑失败时告知最接近的匹配位置
- 🐛 **关键修复**：修复 zsh 中含 `=` 开头词的 Bash 命令（如 `echo ====`、`[ a == b ]`）报 not found 中断
- 🐛 **关键修复**：修复自动压缩复用会话早期系统提示、未按 `/compact` 方式重建的问题
- 🔧 **改进**：`/code-review` 改为聚焦缺陷与 CLAUDE.md 违规，标注重要程度并附修复建议

**📋 更新明细**（共 144 条，按类别归组）

**🚀 新功能**（14 条）

- 为 Amazon Bedrock、Google Cloud 的 Agent Platform、Microsoft Foundry 和 Claude apps gateway 上的 Claude Opus 4.6 与 Sonnet 4.6 新增 auto 模式；未设置权限模式的交互式会话将以该模式启动
- 为 `mcp_tool` 钩子新增 `"onFailure": "block"`，与命令及 HTTP 钩子一致：调用失败的钩子将阻止相应操作
- 新增警告：来自跳过权限提示的会话的消息，可能被云端会话扣留并丢弃
- 当 OpenTelemetry exporter 未配置 endpoint、数据很可能因此丢失时，`/status` 和 `claude doctor` 会显示相应提示
- 新增 `CLAUDE_CODE_DISABLE_DEFERRED_TOOL_RESUME`，让宿主可以阻止 `claude -p --resume` 与 `--continue` 运行被钩子延迟的工具调用
- 新增支持：内嵌 Claude Code 的应用可启用策略插件的 `allowManagedModsOnly` 选项；管理员的托管设置仍优先
- 当策略的 `maxEffortLevel` 不是有效的 effort 级别时，Claude apps gateway 启动时会发出警告
- Self-hosted runner：新增 `--repository-folder`，用于在 `--capacity 1` 时为会话使用的仓库文件夹命名，取代其在基础文件夹下的路径（该路径不能是符号链接）
- Self-hosted runner：当宿主的 settings.json 设置了会被会话忽略的默认权限模式时，启动时会发出警告
- Self-hosted runner：为 `claude self-hosted-runner orchestrator` 新增 `--hook-label`，将指定的会话标签传给 `spawn-runner` 钩子
- Self-hosted runner：为 `claude --environment` 新增 `--metadata key=value`，用于为 `spawn-runner` 钩子标记会话
- Self-hosted runner：在 orchestrator 的 `/metrics` 中新增 `claude_code_self_hosted_orchestrator_session_queue_wait_by_reason_seconds`，以便区分重新打开的会话与新会话的等待时长
- Self-hosted runner：新增 orchestrator 指标 `claude_code_self_hosted_orchestrator_sessions_given_up_total`，按原因统计 Anthropic 放弃为会话启动 runner 的次数
- [VSCode] 当来自其他会话的消息被暂存时新增提示，并附上可允许该消息的设置文件链接

**🔧 改进**（19 条）

- 改进了 `claude -p` 和 SDK 会话，现在会在后台获取拥有独立 git 仓库的 managed-settings 插件，供后续会话使用
- 改进了全新机器上 `claude -p`、SDK 和 Claude Desktop 会话中来自 git marketplace 的 managed-settings 插件的加载速度；短时运行可能最多延迟 30 秒退出
- 缩短了恢复大型会话所需的时间
- 降低了恢复包含大量图片的会话时的内存占用
- 改善了运行慢速命令或工具的长时 SDK 与桌面会话的内存占用和响应速度
- 通过移除大多数脚本执行后的 0.75 秒停顿，提升了 Code Mode 在 auto 和 bypass-permissions 模式下的速度
- 改进了带有 MCP 服务器的新 Code Mode 会话的 prompt 缓存，并会在服务器仍在连接或服务器列表变化时告知 Claude
- 通过更简短的工具描述降低了 Code Mode 的 token 消耗
- Code Mode 现在会在脚本运行时显示其正在执行的命令及输出
- 改进了 Code Mode 的编辑：无实际改动的编辑不再中断脚本，且会告知 Claude 失败的编辑在何处匹配或最接近
- 改进了 Code Mode：脚本失败时会告知 Claude 当时仍在运行的工具调用
- 改进了 Code Mode 在 auto 和 bypass 模式下 Claude 启动开发服务器的方式：Claude 会将其作为后台任务运行，并显示在 `/tasks` 中
- Windows：改进了 Code Mode，现在会告知 Claude 脚本的 shell 命令在 Git Bash 中运行，且 PowerShell 中同名别名会优先于函数执行
- 改进了同时启动多个进程内 teammate 的情况：出现 "Lock file is already being held" 失败的情况大幅减少
- 改进了 computer use 审批对话框：现在会显示每个应用的访问权限级别和更清晰的警告信息
- 改进了跨会话消息功能：当云端会话或另一台计算机未出现在列表中时，Claude 现在会说明 Remote Control 已关闭
- 改进了 `claude -p` 的文本输出：当来自其他会话的消息被暂存或丢弃时，会在 stderr 上输出提示及允许方法
- 改进了 Claude 对“谁可以打开其发布的 artifact”的回答：Claude 现在会重新检查 artifact，而不是重复上次发布时的答案
- 改进了恢复的自托管 runner 会话：Claude 现在会检查先前的工作是否仍然存在，并说明缺失的内容

**🔄 变更**（20 条）

- 对于第三方提供商上的 Opus 4.6 和 Sonnet 4.6，plan mode 和 Bash 提示现在与新模型一样使用并提供 auto 模式；`disableAutoMode` 可将两者一并关闭
- Code Mode 不再对脚本输出运行 UserPromptSubmit hooks（包括托管 hooks）；若要对该输出进行脱敏，请使用带 `updatedToolOutput` 的 PostToolUse hook
- 在大多数模型上，`/code-review` 现在仅报告 bug 和 CLAUDE.md 违规；如需复用、简化和效率方面的清理，请运行 `/simplify`
- 在大多数模型上，`/code-review` 现在会将每项发现标记为 Important、Pre-existing 或 Nit，并在每条摘要末尾给出建议修复；通过审查的列表现在显示为 "Code review found no issues."
- `deniedMcpServers` 中形如 `claude.ai <name>` 的条目现在同样适用于云端和自托管 runner 会话中的相应 connector
- 托管的 `PostToolUse` hooks 不再针对运行前即被拒绝的调用触发：不再产生日志条目、重写、阻止或停止；`PostToolBatch` 仍会接收其中大多数，但不会标记为被拒绝
- `/bug` 现在会在发送前询问 Yes 或 No，重复按 Enter 不再误发报告或打开 GitHub
- 当设置了 `CLAUDE_CODE_FORK_SUBAGENT=0` 时，`claude -p`、Agent SDK、桌面版和 VS Code 中的 subagent 现在默认会等待其自身的 subagent
- 在设置 `CLAUDE_CODE_FORK_SUBAGENT=0` 的 `claude -p` 中，后台 subagent 及其等待的 subagent 现在共享一次 10 分钟的等待额度；更长的链路请调高 `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS`
- 被 PermissionRequest hook 重写为沙箱排除命令的 shell 命令，现在会在沙箱之外运行
- Claude in Chrome 欢迎界面和 `/chrome` 现在会说明：除非权限模式或 `/permissions` 中的规则已给出答案，否则 Claude Code 会在 Claude 对网站执行操作前先行询问
- 使用第三方提供商或关闭遥测/feature flags 的 Claude Desktop 和 Agent SDK 会话，在带有未回答问题时被关闭，现在会结束该回合，而非在没有答案的情况下继续
- 在使用第三方提供商或关闭遥测/feature flags 的情况下，粘贴的文本现在也会为 Claude 标记为粘贴内容
- 对于使用 Anthropic API 的终端会话，subagent 进度摘要现在改由默认小型快速模型根据简短笔记撰写（遥测关闭时同样适用），token 消耗大幅降低
- 更改了沙箱无法启动时的报告方式（除非设置了 `sandbox.failIfUnavailable`）：下一条沙箱化的 Bash 命令将被拒绝，并提示本会话的沙箱已关闭
- `/list-agents` 现在仅向你展示列表；Claude 会在需要时自行列出会话
- 自托管 runner：当设置按名称限制 Claude 的 GitHub 工具时，内置 `gh api` 现在默认关闭；`--use-anthropic-gh true` 可将其开启
- 自托管 runner：在会话自身的 `claude` 启动前或结束后由包装脚本运行的 `claude`，现在不包含 Anthropic 管理的 git
- 自托管 runner：`CLAUDE_RUNNER_SESSION_UUID` 和 `CLAUDE_CODE_REMOTE_SESSION_UUID` 现在会在会话及其 `checkout`、`post-session` 和 `spawn-runner` hooks 中同时设置
- 对于 `--capacity 1` 的自托管 runner，当其推送目标仓库路径为符号链接时，现在会更早地拒绝会话
