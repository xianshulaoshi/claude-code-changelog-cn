# Claude Code v2.1.331 更新日志

> 🗓 2026-11-23 发布 · 📋 135 条更新（🚀 14 · 🔧 18 · 🔄 8 · 🐛 95）

**✨ 本版亮点**

- 🚀 **新功能**：Code Mode 现已支持 Amazon Bedrock、Google Agent Platform、Microsoft Foundry 等云端终端会话
- 🚀 **新功能**：VS Code 新增 "Fix with Claude Code" 快速修复，可一键将错误、警告和失败测试发送到聊天框
- 🔧 **改进**：VS Code 长会话大幅提速：回复流式输出更流畅、权限提示更快、发送卡顿明显减少
- 🔧 **改进**：`claude doctor` 新增 API 连通性检查，直接报告可达状态与 HTTP 错误信息
- 🐛 **关键修复**：修复 MCP 工具调用因服务器异常响应而挂起最长 30 分钟的问题

**📋 更新明细**（共 135 条，按类别归组）

**🚀 新功能**（14 条）

- 在 Amazon Bedrock、Google Cloud 的 Agent Platform、Microsoft Foundry 和 AWS 上的 Claude Platform 的终端会话中新增 Code Mode 支持
- 为 Claude 应用网关新增 `oidc.groups_jsonpath`，可用一小部分 JSONPath（RFC 9535）从对象列表的匹配条目中读取分组
- `claude doctor` 新增 API 连通性检查部分，报告 API 是否可达、HTTP 状态或错误原因，或说明为何未测试
- 新增提示：当点按式语音听写因 15 秒无识别语音或达到 2 分钟上限而自动停止时予以告知
- 新增 `CLAUDE_CODE_DISABLE_RESPONSE_COMPRESSION`，用于在代理截断压缩响应时改为请求未压缩的模型响应；暂不建议在自托管 runner 或 Remote Control 上使用
- 新增 `CLAUDE_GATEWAY_IDP_CONNECT_BY_HOSTNAME=1`（用于 Claude 应用网关）：配合 `oidc.use_proxy: true` 时，即使设置了 `NO_PROXY`，登录请求也会向代理提供 `https` IdP 的主机名
- `claude_code.llm_request` 追踪 span 新增 `gen_ai.usage.*`、`gen_ai.response.model` 和 `gen_ai.operation.name`；`gen_ai.usage.input_tokens` 包含提示缓存 token
- 插件清单新增 `optionalDependencies`：被依赖的插件会随列表安装，且可独立禁用或卸载
- [VSCode] 登出时若撤销 claude.ai 登录的请求未获确认，现在会显示警告及撤销页面的链接
- [VSCode] 发送过大的选中内容或附件文本文件前会先提示，并在 "Prompt is too long" 下方给出建议，指出过大的部分及后续操作
- [VSCode] 在笔记本单元格菜单中新增 "Add Cell to Chat"，可将单元格连同其输出或错误一起附加
- [VSCode] 新增 "Fix with Claude Code" 快速修复，可用于错误和警告，以及测试查看器和 Test Results 视图中失败的测试，将问题直接放入聊天框
- [VSCode] 在源代码管理视图中已更改文件的右键菜单中新增 "Add to Chat"
- [VSCode] 在存在合并冲突的文件编辑器标题栏及源代码管理的 Merge Changes 分组中新增 "Resolve Merge Conflicts"

- 提升屏幕阅读器模式下的输入速度，长会话中改善尤为明显

- Windows：提升无自定义 shell 启动文件的机器上会话中首条 Bash 命令的速度

- 改进了 /login 和 `claude auth login --console` 显示的 Console 登录链接，现在短得多
- 改进了 Claude 展示你的 artifacts 的列表：现在会标记网页，减少 Claude 尝试用 Claude Docs 连接器打开网页的情况
- 改进了矮终端下的目录信任提示：全屏 `/cd` 和 `/add-dir` 用更少的行数显示选项，启动时的提示在警告很多时也会保持目录路径可见
- [VSCode] 改进了已安装 Python 扩展但文件夹中没有 Python 时新文件夹中首条回复的时间
- [VSCode] 改进了登录界面，现在会说明其因请求被拒绝而打开
- [VSCode] 提升了长对话的打开、恢复和切换速度，在包含大量文件编辑或 git 较慢的场景下提升尤为明显
- [VSCode] 提升了长聊天中的响应速度：回复流式输出时输入流畅、大文件写入更顺畅，权限提示更快，且开启辅助功能时发送几乎不再卡顿
- [VSCode] 改进了启动速度和内存占用：面板和新聊天标签页打开更快，新标签页中首条消息得到更快的回复，Pro 和 Max 套餐下文件夹信任对话框出现更早
- [VSCode] 提升了远程窗口（SSH、WSL、容器）中的速度：面板启动、回复显示和会话重新打开都更快
- [VSCode] 改进了低内存机器上聊天空闲数分钟后首条消息获得响应的时间
- [VSCode] 改进了慢速磁盘或被杀毒软件扫描的磁盘上聊天的启动、从历史打开以及重启后恢复的速度
- [VSCode] 改进了重新打开的对话中 diff 的显示速度，并移除了不起作用的 diff 菜单项
- [VSCode] 改进了 @ 文件菜单，现在优先列出已打开编辑器标签页的文件，最近使用的排在最前

**🔄 变更**（8 条）

- 调整了 `/ide` 中停止自动连接的询问，以及子代理视图中 `/clear`、`/compact` 或 `/rewind` 的询问，将 Yes 排在首位；默认仍停留在 No，因此按 Down 再回车即选择 No
- 调整了 `PermissionDenied` 钩子 `retry: true` 对 Claude 的含义：仅在你要求过该调用时才重试被拒绝的调用
- 变更预告：在 2026 年 11 月 30 日当天或之后的版本中，托管 `extraKnownMarketplaces` 中的插件市场将默认自动更新。如需为某个市场关闭自动更新，请在其条目上设置 `"autoUpdate": false`
- Windows：调整了使用注册表托管设置时的启动流程：升级前请先检查，因为 `HKLM` 策略优先级高于 `managed-settings.json`，损坏的值可能导致启动失败
- [VSCode] 变更了建议 diff 的保存行为：仅在你点击或在其建议侧（右侧）输入后才接受；保存被拒绝或带保存的关闭未应用任何内容时会显示通知
- [VSCode] 变更了来自终端会话的 diff 打开方式：不再移动键盘焦点，并在含未保存更改的文件旁打开；要回答请点击 Accept 或使用终端
- [VSCode] 变更了权限卡片：设置 `allowManagedPermissionRulesOnly` 且卡片会提供允许规则时，仅显示“是”和“否”；这些卡片上按 2 现在表示“否”
- [VSCode] 变更了 Claude 标签页行为：当其查找框失去键盘焦点时忽略 Enter 并显示提示
