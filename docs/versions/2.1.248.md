# Claude Code v2.1.248 更新日志

> 🗓 2026-08-27 发布 · 📋 49 条更新（🚀 7 · 🔧 5 · 🔄 5 · 🐛 32）

**✨ 本版亮点**

- 🚀 **新功能**：新增 --restricted 受限模式：禁用命令执行与 WebFetch 等工具，适用于高风险运行环境
- 🚀 **新功能**：跨会话消息（SendMessage/ListAgents）现已支持 Bedrock、Vertex、Foundry 及关闭遥测的场景
- 🐛 **关键修复**：修复长会话中每小时一次的提示词缓存失效导致扩展思考上下文丢失的问题
- 🐛 **关键修复**：修复 Claude Desktop 会话 30 天后被清理消失的问题，应用内会话现予保留
- 🔧 **改进**：Workflow 工具描述从 5.7k tokens 精简到约 1k，显著降低提示词开销

**📋 更新明细**（共 49 条，按类别归组）

**🚀 新功能**（7 条）

- 新增 `--restricted`（或 `CLAUDE_CODE_RESTRICTED=1`）：移除内置的命令/代码执行工具及 `WebFetch`（除非通过 `--tools` 指定），文件工具限制在工作目录内，拒绝 `bypassPermissions`，并忽略用户、项目和本地设置文件
- 在 agent frontmatter 中新增 `experimental.cacheTtl`（`"5m"` 或 `"1h"`）：当未配置 subagent TTL 设置时，作为单个 agent 的提示词缓存 TTL
- 新增 `claude self-hosted-runner --client-label <label>`（或 `SELF_HOSTED_RUNNER_CLIENT_LABEL`）：覆盖 runner 注册时使用的标签（默认为主机名）
- 新增服务器管理设置的诊断信息：设置加载失败时启动会发出警告，并在 `/doctor` 和 `/status` 中解释加载失败或未获取的原因（Bedrock/Vertex/第三方提供商、自定义 `ANTHROPIC_BASE_URL`）
- 在 `/web-setup` 中新增警告：当 GitHub CLI token 缺少 `workflow` scope 时提示，因为缺少它时向超大仓库推送可能被拒绝
- 新增 `/usage-credits`：面向通过 AWS Marketplace 计费的企业组织、自助 Enterprise 和 Enterprise 试用版，成员可向管理员申请提高用量上限
- 跨会话消息（`SendMessage` / `ListAgents`）现可在同一机器上的会话之间使用，覆盖 Bedrock、Vertex 和 Foundry，以及遥测被禁用的情况

**🔧 改进**（5 条）

- 优化 Workflow 工具的提示词占用：其描述现在约为 1k tokens（原为 5.7k），脚本编写参考已移至打包的 `workflow-authoring` skill
- 优化提示词底部 PR 徽章：在 PR 未变化时减少对 GitHub 的查询频率；推送或执行 `gh pr` 命令仍会立即刷新
- 优化托管设置：客户端超时、MCP 启动模式和流 watchdog 的环境变量不再触发设置审批提示
- 优化 `/ultrareview <PR#>`：启动前检查与 Claude 账户关联的 GitHub 账户能否访问仓库，并说明修复方法，而不是在云会话启动后才失败
- 优化跨会话消息：当默认目录无法使用时回退到每个用户的私有 `/tmp` 目录，通知和 `/status` 会指明需要修复的目录

**🔄 变更**（5 条）

- 变更：agent view 分发输入框中的 shift+enter 现在插入换行符（与提示框一致）；ctrl+enter 现在执行分发并附带
- 变更 `/loop`：自主步调的动态模式和无提示自主默认模式现在始终可用，包括 Bedrock/Vertex/Foundry
- 变更：Anthropic 遥测导出失败现在以 debug 级别记录为 `[Anthropic telemetry]`，而不是 `[3P telemetry] OTEL diag error`，避免被误认为是你自己的 OTel collector 故障
- 变更 Linux 用户命名空间中的跨会话消息：对未映射所有者的 root 等效信任现在仅限于规范系统目录
- 变更 subagent 向其他会话发送的 `SendMessage`：结果现在会注明任何回复将送达父会话的对话，而不是该 subagent

**🐛 修复**（32 条）

- 修复长会话中大约每小时出现一次提示词缓存未命中（及扩展思考上下文丢失）的问题，原因是在 OAuth token 刷新后工具定义被重新渲染
- 修复当账户进入超额用量时，`ScheduleWakeup` 工具定义在会话与其 `--resume` 之间发生变化，导致恢复后的会话首回合出现完整提示词缓存未命中
- 修复 Claude Desktop 和 Cowork 会话在 30 天后消失的问题：transcript 清理现在会保留应用内的 desktop 会话（除非组织策略管理保留期）；新增 `desktopSessionCleanupPeriodDays` 设置可限制该豁免
- 修复当另一个 Claude Code 进程持有 token 刷新锁而会话 token 已过期时，被送到登录界面的问题；现在该请求会以可重试的错误失败
- Windows：修复 `claude agents` 列表在从会话分离后，或在 win32-input-mode 终端标签页中启动时，不响应键盘输入的问题
- 修复在无法使用推荐 Console 登录的机器上（例如设置了 `ANTHROPIC_API_KEY` 或 API key helper 时），`/login` 中推荐的 Console 登录在显示登录 URL 之前以 OAuth 错误失败的问题；现在会回退到 API-key 登录
- 修复 `/model` 和 fast-mode 切换通知中的模型名称渲染为代码格式，使 `[1m]` 等后缀按字面显示而不是渲染为链接
- 修复 `claude agents` 在设置了 `CI` 环境变量时跳过工作区信任提示的问题
- 修复 `claude agents` 在 PR 状态缓存中存在格式错误条目时启动崩溃的问题
- 修复 agent view 在机器关机后复活数周前的后台会话的问题：此类会话现在会显示为在其真实结束时间停止，打开时会先询问是否恢复保存的对话
- 修复 agent view 在开始新会话时偶尔打开较旧的对话并丢失已输入提示词的问题
- 修复 `claude agents`：打开你已在另一个终端中恢复的已停止会话时，不再在该对话上启动第二个进程；该行现在会显示它已在某个终端中打开
- 修复 `claude agents` 和 `claude rm` 拒绝删除会话（"has commits that are not pushed anywhere"）的问题：当会话的 worktree 分支已合并到你检出的默认分支（例如本地 `main`）但尚未推送时
- 修复后台会话在 `PermissionRequest` 或 `PreToolUse` hook 输出无效答案时静默等待的问题：`claude agents` 行现在会指明 hook 名称和 schema 错误
- 修复 hooks 将 stdout 中非有效 JSON 的 `{…}` 对象静默当作纯文本处理的问题；现在会将其报告为 hook 错误并附带解析信息
- 修复 `/mcp` 将声明 claude.ai connector 类型的项目 `.mcp.json` 条目列在受信任的 "claude.ai" 标题下的问题；现在会显示在其真实作用域下
- 修复 `headersHelper` 提供 `Authorization` 头的 MCP 服务器在收到 401 时进入 OAuth 发现流程的问题；现在会按文档所述重新运行 helper 并重试调用
- 修复登录 Claude apps 网关时，在需要 managed-settings 安全审批对话框的情况下 `/login` 挂起的问题
- 修复当 `apiKeyHelper` 是唯一凭证时，网关模型发现（`CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY`）从不运行的问题
- 修复 `claude logs` 在其运行的终端中遗留鼠标跟踪、括号粘贴和备用屏幕模式的问题
- 修复信任对话框中的仓库权限规则列表在长规则于 emoji 中间被截断时显示乱码字符的问题
- 修复在 ctrl+c 之后立即按 shift+tab 时，权限模式指示器被 "Press Ctrl-C again to exit" 提示遮挡的问题
- 修复 `/ultrareview` 和本地种子化的云会话上传未提交的 `prod.env` 类及 `*.tfvars` 文件编辑，或凭证文件的编辑器交换、临时和备份副本（例如 `key.pem.tmp`、`id_rsa.swo`）的问题；这些文件现在保留在你的机器上
- 修复 Remote Control 会话在 CLI 静默重连后偶尔不显示权限提示或最新消息的问题
- 修复云会话在容器会话凭证尚不可读时偶尔启动失败的问题
- 修复 `claude remote-control` 在全局 flag 或 wrapper 注入的选项位于子命令之前时，拒绝其自身 flag（例如 `--spawn`、`--name`）的问题
- 修复启动警告（例如 "N MCP servers need authentication"）渲染位置比其余 transcript 偏右一列的问题
- 修复后台 worktree 会话丢失其 checkout 的问题：后台会话现在在运行期间持有 worktree 的锁，因此清理和 `git worktree remove` 不会影响它
- 修复 @-mention 其他会话时无法匹配以非拉丁字符（例如通过 IME 输入的韩文）输入的名称的问题
- 修复无效的 `crossSessionInbound` 值被静默忽略的问题：现在会发出警告并暂存跨会话消息（用户设置），或拒绝消息（托管设置），直至修复
- 修复速率限制、用量和 fast-mode 消息提示运行 `/usage-credits` 但该命令对你的组织不可用（例如被 `DISABLE_EXTRA_USAGE_COMMAND` 隐藏）的问题
- [VSCode] 修复聊天标签页在其会话从未保存时卡在 "No conversation found" 的问题；现在会改为开始新对话
